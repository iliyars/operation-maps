# Roadmap

Контекст: WPF-приложение для подготовки карт эксплуатации электронных
компонентов (импорт XML → сопоставление с каталогом → редактирование форм →
экспорт в Word по ГОСТ-шаблонам). Сейчас используется небольшой командой,
в далёкой перспективе возможен переход в коммерческий продукт.

Статус: ранняя стадия, архитектура и функциональность ещё активно меняются.

Этапы идут по приоритету, без привязки к датам. Внутри этапа порядок пунктов
не строгий — можно брать то, что сейчас удобнее.

## Этап 3 — UI/UX WPF-приложения

Цель: сократить трение в повседневной работе команды с формами. Для Ильи
это самая сложная область — двигаемся точечно по экранам на основе
скриншотов и конкретных жалоб, а не переделываем всё разом вслепую.

- [x] Экран "Компоненты" (список + фильтры), первый проход по реальным
      скриншотам:
      - у вкладок фильтра "Все/Найдены/Не найдены" не было видимого
        активного состояния — добавлен `EnumEqualsToBoolConverter`,
        активная вкладка теперь с акцентным подчёркиванием и жирным текстом
      - лёгкое чередование фона строк таблицы для сканируемости
      - у `MainWindow` не было `MinWidth`/`MinHeight` — окно ужималось
        так, что часть колонок таблицы (820px) + панель деталей (300px)
        + сайдбар (220px) переставали помещаться; поставил
        `MinWidth="1360"`/`MinHeight="600"`
      - алерт "Семейство найдено, но не хватает данных" не переносил
        текст (`TextWrapping`) и использовал захардкоженные светлые
        цвета (`#E8F0FE`/`#4285F4`/`#1A73E8`) — в тёмной теме превращался
        в белое пятно. Завёл токены `StatusInfoBrush`/`StatusInfoBgBrush`
        в обеих темах (`LightTheme.xaml`/`DarkTheme.xaml`)
- [ ] Остальные экраны (Welcome, OwnForm, диалог добавления компонента) —
      по мере поступления скриншотов/жалоб
- [ ] Пройтись по рабочим сценариям (импорт → матчинг → редактирование →

## Этап 4 — Импорт из заполненных Word-документов

Цель: помимо XML-перечня, уметь забирать данные компонентов из уже
заполненного вручную комплекта карт (Word) — не перепечатывать то, что
у Ильи уже есть в виде готовых форм.

- [x] Выяснили реальную структуру исходного документа на настоящем файле
      заказчика (не гадали): один .docx содержит МНОГО форм подряд (Форма 4,
      67, 64, 77, 68, 55, 60, 75, ...), и один и тот же номер формы может
      повторяться в НЕСКОЛЬКИХ таблицах подряд, если компонентов больше, чем
      слотов на страницу (в реальном файле так было с Формой 4 — 3 таблицы,
      Формой 67 и 68 — по 2 таблицы каждая)
- [x] `WordFormReader.Read` раньше читал слоты формы из ВСЕХ таблиц
      документа подряд — безопасно только когда в файле одна форма. Добавил
      фильтр по заголовку таблицы (`ФОРМА N`), чтобы чтение конкретной формы
      не цепляло чужие таблицы из смешанного документа. Плюс новый
      `WordFormReader.DetectFormNumbers` — сканирует документ и возвращает,
      какие номера форм в нём вообще есть. Все 9 существующих round-trip
      тестов не сломались
- [x] Мимоходом нашёл реальный баг в `WordReportBuilder` (существующий,
      но нигде не подключённый и ничем не покрытый код для сборки финального
      комбинированного отчёта): читал `ms.ToArray()` ДО `Dispose()`
      пакета — zip-пакет ещё не сбросил изменения в поток, метод тихо
      возвращал байты исходной обложки без единой добавленной формы. Исправил
      порядок (dispose до чтения байт)
- [x] Новый `IWordCatalogImportService` (Application) +
      `WordCatalogImportService` (Infrastructure): сканирует документ,
      сопоставляет каждый компонент own-формы (Форма 67/68/...) с его
      слотом в Форме 4 по префиксу "Обозначения" (например own-form
      "К10-84в 3216М-50 В..." сопоставляется с Form4-слотом "К10-84в"),
      определяет тип/семейство тем же способом, что и `ComponentMatcher`
      при XML-импорте (`IComponentNameParser`, поиск `Family` по
      `(ComponentTypeId, Name)`), помечает уже существующие в каталоге
      компоненты (не дублирует), собирает `NewComponentInput` и создаёт
      компонент через ТОТ ЖЕ `IComponentEntryService`, что и мастер
      "Ввести данные компонента". Формы без `map.json`/без записи в БД —
      в список "не поддерживается", не блокируют импорт остальных
- [x] Проверено на реальном файле заказчика (не синтетика): из 11
      компонентов на плате 9 сопоставились автоматически, 2 — реальные
