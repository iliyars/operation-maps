# Roadmap

Контекст: WPF-приложение для подготовки карт эксплуатации электронных
компонентов (импорт XML → сопоставление с каталогом → редактирование форм →
экспорт в Word по ГОСТ-шаблонам). Сейчас используется небольшой командой,
в далёкой перспективе возможен переход в коммерческий продукт.

Статус: ранняя стадия, архитектура и функциональность ещё активно меняются.

Этапы идут по приоритету, без привязки к датам. Внутри этапа порядок пунктов
не строгий — можно брать то, что сейчас удобнее.

Цель: сократить трение в повседневной работе команды с формами. Для Ильи
это самая сложная область — двигаемся точечно по экранам на основе
скриншотов и конкретных жалоб, а не переделываем всё разом вслепую.

- [x] Экран "Компоненты" (список + фильтры), первый проход по реальным
      скриншотам:

        активного состояния — добавлен `EnumEqualsToBoolConverter`,
        активная вкладка теперь с акцентным подчёркиванием и жирным текстом
      - лёгкое чередование фона строк таблицы для сканируемости
      - у `MainWindow` не было `MinWidth`/`MinHeight` — окно ужималось
        так, что часть колонок таблицы (820px) + панель деталей (300px)
        + сайдбар (220px) переставали помещаться; поставил
        `MinWidth="1360"`/`MinHeight="600"`
      - алерт "Семейство найдено, но не хватает данных" не переносил
        текст (`TextWrapping`) и использовал захардкоженные светлые
        цвета (`#E8F0FE`/`#4285F4`/`#1A73E8`) — в тёмной теме превращался
        в белое пятно. Завёл токены `StatusInfoBrush`/`StatusInfoBgBrush`
        в обеих темах (`LightTheme.xaml`/`DarkTheme.xaml`)
- [x] Собственный заголовок окна вместо системного (как в VS Code):
      `WindowStyle="None"` + `WindowChrome` (сохраняет нативные drag-move,
      resize по краям и Aero Snap бесплатно — кнопки свернуть/
      развернуть/закрыть просто помечены `IsHitTestVisibleInChrome`, а не
      реализованы вручную). Плюс строка меню (Файл/Правка/Вид/Справка) —
      меню и MenuItem полностью перешаблонены (`MenuStyles.xaml`), т.к.
      дефолтный вид Menu игнорирует тему приложения. Правка > Отменить/
      Повторить — сознательно НЕ на общий стек (у `ProjectStore.History`
      нет ни одного подписчика, каждая `OwnFormViewModel` ведёт свою
      историю — отмена в Форме 67 не должна отменять правку в Форме 68),
      а делегирует в Undo/Redo активного экрана, если это OwnForm; иначе
      пункты меню просто неактивны — так честнее, чем кнопка, которая
      выглядит рабочей, но ничего не делает
- [x] Тот же заголовок окна — на ВСЕХ окнах приложения (диалоги
      `AddComponentDialog`/`WordImportDialog`/`SplitDialog`), не только на
      главном. **Реальный баг по пути**: первая версия рисовала титульную
      полосу прямо в `ControlTemplate` окна (общий неявный `Style
      TargetType="Window"`), а цвета внутри задавала через
      `DynamicResource` — Илья заметил, что полоса всегда белая независимо
      от темы. Промежуточная попытка (протащить цвета через `Setter`
      окна + `TemplateBinding`, как уже работал `Background`) тоже не
      помогла. Оказалось, дело не в способе передачи значения, а в том,
      что сама полоса лежала ВНУТРИ шаблона окна — вынес её в обычный
      `UserControl` (`Shared/Controls/CustomTitleBar.xaml`), который
      каждое окно подключает как обычный контент (первая строка своего
      Grid), а не как часть шаблона — тот же `SidebarBgBrush` в обычном
      контенте (например, в сайдбаре `ShellView.xaml`) тему подхватывал
      всегда корректно, только внутри `Window.Template` — нет.
      **Второй реальный баг по пути**: после переноса титульной полосы в
      `UserControl` стали видны ДВЕ полосы — нативная Windows (белая) и
      новая тёмная поверх неё. Оказалось, `WindowStyle="None"`, заданный
      через общий неявный `Style TargetType="Window"`, не успевает
      примениться до создания нативного заголовка окна. Убрал общий
      `Style` — `WindowStyle="None"` теперь прямой атрибут на каждом окне
      (как в самой первой рабочей версии); только `WindowChrome` (у него
      такой проблемы нет) остался общим — расшарен как
      `x:Key="AppWindowChrome"` в `AppStyles.xaml` с `x:Shared="False"`
      (у каждого окна обязан быть свой экземпляр — `WindowChrome` хранит
      состояние конкретного окна, один и тот же объект нельзя
      переиспользовать между несколькими одновременно открытыми окнами).
      Кнопки свернуть/закрыть общие для всех окон — ищут своё окно через
      `Window.GetWindow(sender)`, а не жёстко привязаны к одному экземпляру.
      **Третий баг**: после исправления темы разворачивание окна ("Развернуть")
      съезжало за границы экрана — сверху появлялась чёрная полоса, снизу
      обрезалось. Классическая проблема `WindowChrome`: без хука
      `WM_GETMINMAXINFO` разворачивание считает размер по ВСЕМУ монитору,
      а не по рабочей области (без панели задач) — то, что обычное окно
      получает от Windows бесплатно, `WindowChrome`-окну приходится
      считать самому. Добавил `MaximizedBoundsFix` (P/Invoke на
      `MonitorFromWindow`/`GetMonitorInfo`), подключается один раз в
      конструкторе каждого окна. После этого старый компенсирующий
      отступ (`WindowStateToMaximizedMarginConverter`, решал другую грань
      той же проблемы) стал лишним и давал чёрную полосу сверху при
      разворачивании — конфликтовал с уже правильно посчитанными
      `MaximizedBoundsFix` границами. Убрал конвертер полностью
- [x] Ховер на кнопках свернуть/развернуть был почти незаметен —
      `BgHoverBrush` рассчитан на контраст с фоном панелей, а не с фоном
      титульной полосы (`SidebarBgBrush`), в обеих темах они почти
      совпадают. Заменил на полупрозрачный серый оверлей (как у нативных
      кнопок Windows 11) — работает поверх любого фона
- [x] После наведения порядка с `WindowStyle` выяснилось: у
      `WindowChrome`-окна пропали закруглённые углы Windows 11 — следствие
      `GlassFrameThickness="0"` (DWM перестаёт считать окно обычным
      композитным). Поменял на `"-1"` (стекло на всё окно) и явно запросил
      скругление через `DWMWA_WINDOW_CORNER_PREFERENCE` (P/Invoke,
      `WindowChromeFixes`, переименован из `MaximizedBoundsFix` — теперь

- [ ] Анимация свернуть/развернуть окна по-прежнему отсутствует —

- [ ] Пройтись по рабочим сценариям (импорт → матчинг → редактирование →
      экспорт) и убрать точки трения, которые мешают ежедневно

Цель: помимо XML-перечня, уметь забирать данные компонентов из уже
заполненного вручную комплекта карт (Word) — не перепечатывать то, что
у Ильи уже есть в виде готовых форм.
