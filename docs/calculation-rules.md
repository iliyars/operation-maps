# Расчёты: текущее поведение и решения перед v1.0

Это описание текущего кода, а не подтверждение инженерной методики.
Правила ниже не изменены при удалении старых команд и добавлении CI.

## Суммы параметров

Поддерживается запись rowN+rowM, где N и M — положительные номера обычных
строк формы. Пробелы вокруг слагаемых и регистр row несущественны.
Повторение строки учитывает её повторно. Другие операции и константы
не поддерживаются; некорректная запись даёт пустой результат.

Значения читаются из «в схеме». Десятичная запятая заменяется точкой,
разбор использует double и InvariantCulture. Пустые/нечисловые операнды
пропускаются. Если чисел нет, результат пустой. Поэтому row1+row2 при
row1=5 и пустом row2 сейчас даёт 5. NaN, Infinity и переполнение суммы
не выдаются как результат. Формат суммы использует текущую культуру Windows.

Пересчёт выполняет состояние формы, независимо от посещения экрана.
Зависимости формул считаются перед потребителями; цикл вызывает ошибку
вместо бесконечной рекурсии. Сначала вычисляются суммы, затем коэффициент.

Решение перед завершением R1: допустима ли частичная сумма, либо до
заполнения всех слагаемых результат должен быть неизвестным? Отдельно
нужно определить разницу между неприменимым слагаемым, пустым полем и
ошибочным текстом. Нельзя автоматически считать любой пропуск нулём
без подтверждения инженерной методики.

## Коэффициент нагрузки

Текущая формула: max(0,1; abs(значение в схеме / значение по НТД)).
Результат округляется для отображения до двух знаков, десятичный разделитель
— запятая; в скобках добавляется номер базовой строки. Верхнего ограничения
нет: 20 / 10 даёт «2 (N)», а 0 / 10 — «0,1 (N)».

Отсутствующая/неизвестная база, нечисловые данные, нулевой знаменатель,
NaN/Infinity и переполнение дают пустой результат и очищают прежнее значение.
При изменении НТД через выбранное условие коэффициент пересчитывается.
Явно снятая база сохраняется пустой в .omaps v4.

Решения перед завершением R1:

- Подтвердить нижнюю границу 0,1, включая нулевое значение «в схеме».
- Подтвердить применение абсолютного значения к отрицательным данным.
- Определить, когда превышение 1 допустимо и нужно ли отдельное замечание
  проверки проекта; сейчас верхнего ограничения и такой диагностики нет.
- При необходимости различать правила по формам/параметрам, а не вводить
  новую универсальную формулу без примеров.

Самодостаточный снимок НТД и контролируемое обновление справочника относятся
к R2. Проверка чисел и сохранение выбора базы не заменяют этот этап.
