# Аудит кода operation-maps

Дата: 2026-11-05. Проверялось текущее рабочее дерево, включая незакоммиченные
изменения. Код приложения и пользовательские документы не изменялись.
Результат планирования — [ROADMAP.md](../ROADMAP.md).

## Объём и способ проверки

Инвентаризация всего дерева src/tests, проектов, ресурсов, миграций,
документации и скриптов; поиск TODO, заглушек, асинхронных обработчиков,
путей сохранения и зависимостей. Углублённое чтение ключевых путей:
запуск/DI → импорт XML/Word → сопоставление → состояние проекта →
редактирование/расчёты → save/open/recovery → проверка → Word/объединение.
Дополнительно проверены история навигации, конфигурация каталога,
транзакции, основные ViewModel/XAML и существующее покрытие тестами.

Инвентарь: 237 файлов C#/XAML в src (включая сгенерированные миграции,
без bin/obj), 40 C#-файлов тестов. Инвентаризация не означает построчную
верификацию каждого файла. Это статический обзор и прогон имеющихся тестов,
а не доказательство отсутствия других дефектов.

Команда проверки:

```powershell
dotnet test OperationMaps.slnx --no-restore --verbosity minimal
```

Результат: 274 passed, 0 failed, 0 skipped, длительность тестового запуска
29 секунд. Сборка Debug успешна; компилятор сообщил nullable-предупреждения
в тестах. Release publish, чистая Windows, живой сетевой каталог и визуальная
проверка Microsoft Word в этот аудит не входили.

## Архитектурная оценка

Основа пригодна для развития: MVVM, DI, отдельные импортёры и Word-сервисы,
пакетное сопоставление, состояние форм на время проекта, атомарная замена
файла .omaps, ревизии состояния, аварийные копии, миграции и SQLite backup API.
Существующие тесты охватывают значительно больше импорта: сохранение,
режимы/примечания, формы, справочник, фоновую работу, Word и persistence.

Главная граница ответственности пока размыта между WPF и Application:
состояние проекта, расчёты и оркестрация выпуска находятся преимущественно
в WPF. ShellViewModel — 741 строка, OwnFormViewModel — 691,
CatalogViewModel — 615. Размер сам по себе не дефект; выносить прежде всего
расчёты и сценарий экспорта, чтобы они работали без посещения экранов.
DatabaseSeeder — 5469 строк, преимущественно данные форм; его переписывание
не первоочередная задача релиза.

## Дополнительные проверки, а не заявленные баги

- Снятие базы коэффициента: OwnFormState.RecalculateLoadFactor возвращается
  при отсутствии базы до очистки результата; проверить достижимость из UI
  и после восстановления/изменения каталога.
- LoadFactorCalculator использует double.TryParse без IsFinite; проверить
  NaN/Infinity, переполнение, отрицательные значения и инженерные правила.
- MergeComponentsCommand создаёт новую ProjectComponentVm без переноса
  пользовательских примечаний/ActiveRegime; проверить вызовы и последствия
  для уже заполненных форм. Проверять отдельно от объединения столбцов,
  где уже появился ColumnMergePlan с явным разрешением конфликтов.
- NavigationService меняет текущий экран и стеки до успешной инициализации,
  не сериализует переходы. Проверить быстрый повторный переход и исключение.
- ComponentsViewModel подписывается на singleton ProjectStore анонимным
  обработчиком; проверить накопление transient-экранов и подписчиков.
- XML-импорт явно читает Windows-1251 и пропускает часть нераспознанных
  строк. Определить поддерживаемые кодировки и видимость потерь пользователю.
- WordDocumentMerger переносит отсутствующие стили, но совпадающий StyleId
  с другой семантикой требует проверки на реальных шаблонах.
- Проверка НТД формы 4 проходит по загруженным строкам; проверить случай,
  когда обязательная строка целиком отсутствует в данных.
- Производительность больших каталогов: ComponentMatcher читает все
  компоненты для Unicode-нормализации. Три запроса сами по себе не
  гарантируют приемлемое время/память; сначала измерить.

- Старые ProjectDbContext/миграции и WordReportBuilder существуют, но
  рабочее сохранение — JSON, итоговая сборка — WordDocumentMerger.
  Очищать старые ветки после проверки ссылок и тестовых фикстур.

## Решение по приоритетам

Сначала воспроизводимая база и целостность редактирования/расчётов,
затем снимки проекта, надёжный справочник и достоверный экспорт.
После них — измеренная производительность, UX, эксплуатация и пилот.
Новые формы добавлять по утверждённому списку, косметику и большой
рефакторинг не ставить впереди корректности инженерных данных.

Процент готовности и календарный срок по результату этого обзора не
назначаются: не утверждён перечень обязательных форм и не выполнена
визуальная приёмка печатных комплектов. Технические критерии завершения
каждого этапа зафиксированы в новом roadmap.

## Выполнено после аудита, 2026-11-05

Первый набор исправлений R1:

- A01: Undo восстанавливает исходные объекты для обоих порядков выбора;
  регрессии проверяют соседние/разнесённые строки и повторные undo/redo.
- A05: параметр активного экрана хранится отдельно и переносится в историю
  вместе с этим экраном. Проверены повторные Назад/Вперёд, null и начальный
  переход без добавления в историю. Гонки переходов/откат при ошибке
  инициализации остаются отдельной незавершённой задачей.
- Уточнение A01: MergeComponentsCommand не вызывается из текущего UI;
  рабочий путь объединения столбцов использует ColumnMergePlan.
  Исправление Undo не означает завершения проверки сохранности данных
  всех преобразований проекта.

Продолжение R1 — расчёты без экранной ViewModel:

- A03: суммы rowN перенесены в ParameterFormulaCalculator (Application),
  порядок пересчёта и зависимости — в OwnFormState. Сначала формулы,
  затем коэффициент нагрузки; обновление экрана не записывает результат
  обратно как пользовательскую правку.
- Пересчёт работает при изменении значения, добавлении/восстановлении
  столбца, замене параметров, синхронизации условий и открытии .omaps.
  Новый снимок не сохраняет результаты формул; устаревшие результаты
  из старых файлов пересчитываются.
- Коэффициент очищается при сбросе/неизвестной базе или недопустимом
  знаменателе. NaN/Infinity и переполнение не выдаются как числовой результат.
- Сохранена прежняя семантика частичных сумм: отсутствующие и нечисловые
  операнды пропускаются, при отсутствии чисел результат пустой. Изменение
  этой инженерной политики остаётся отдельным пунктом roadmap.
- Добавлены проверки пересчёта без экрана и данных Word, открытия проекта
  с устаревшей суммой, обновления UI без лишнего dirty, замены столбцов,
  объединения/undo/redo, зависимостей формул и нечисловых результатов.

Продолжение R1 — навигация и выбор типа Word-импорта:

- Переключение экранов защищено отдельным асинхронным шлюзом; инициализация
  не удерживает его, поэтому с загружающегося экрана можно уйти.
  Передача отмены и версия перехода предотвращают возврат устаревшего экрана.
- Ошибка актуальной инициализации восстанавливает предыдущий экран,
  его параметр и оба стека истории; предыдущий экран повторно активируется.
  Ошибка DI до переключения не меняет историю и не вызывает уход.
  Ошибки повторной активации при восстановлении записываются в журнал.
- WordImportRowVm передаёт сервису отдельный черновик на каждый запрос;
  проверка версии выполняется до копирования результата в Model.
  Пока тип определяется или определение завершилось ошибкой, строка
  не участвует в импорте. Ошибка показана в строке и перехвачена.
- Уход и перечитывание документа отменяют запросы строк. Даже сервис,
  игнорирующий отмену, не может применить старый черновик.
- ResolveComponentTypeAsync записывает набор полей только после успешных
  запросов и проверки отмены, без промежуточного частичного изменения.
- Регрессии управляют завершением задач без sleep: поздний успех/ошибка,
  A → B → A, ошибка/отмена актуального перехода, ошибочный Назад,
  сохранение обоих стеков, одновременный уход, ошибка DI,
  отмена строки и восстановление после ошибки определения типа.
- Общая проверка НТД-загрузки выбранного компонента и отписок transient-
  экранов остаётся открытой; этот набор исправлений не закрывает весь R1.

Продолжение R1 — НТД и подписки экранов:

- ProjectComponentVm сериализует загрузки на уровне компонента: второй
  потребитель ждёт результат вместо возврата с пустыми данными.
  После отмены ожидающий повторный запрос может выполнить новую загрузку.
  Перед публикацией проверяются токен и исходный ComponentMatchEntry;
  изменение сопоставления не допускает применения данных прежнего семейства.
- ComponentsViewModel отменяет старый выбор и загрузку при уходе;
  ошибки наблюдаются, только актуальная ошибка показывается в панели.
  Возврат на экран загружает выбранный компонент заново при необходимости.
- ComponentRegimesViewModel поддерживает связанный токен загрузки,
  отмену и проверку версии; отмена не становится ошибкой для пользователя.
- Именованные обработчики снимаются при уходе с Components/Catalog,
  повторный вход не дублирует подписку на ProjectStore/SessionStore.
  Transient-экранам не добавлен IDisposable: при разрешении из корневого
  DI-контейнера это само создало бы удержание до завершения приложения.
- Тесты управляют запросами через TaskCompletionSource и EF interceptor:
  A → B → A, поздняя ошибка, уход/возврат, отменённый SQL и ожидающий
  повторный потребитель, смена семейства, уведомления только активного
  экрана и восстановление одной подписки после повторных входов.
- Отдельный аудит выбора карточек каталога и загрузок формы 4 остаётся
  открытым. Проверка подписок не является профилированием всего приложения.

Продолжение R1 — карточки справочника и форма 4:

- Устранено присваивание Card до проверки актуальности семейства.
  Семейство/компонент/предпросмотр используют единую версию выбора и
  связанные токены. Повторный быстрый выбор разрешён командами;
  старые ответы и ошибки не меняют новую карточку, A → B → A различается.
- Дерево справочника защищено версией загрузки и временем жизни экрана.
  Уход отменяет загрузку; возврат не принимает результат предыдущего входа.
  Ошибка актуальной карточки отображается отдельно; успешный выбор её очищает.
  Завершение подтверждения компонента не заменяет новую выбранную карточку.
- Форма 4 собирается во временные группы/параметры из снимка компонентов.
  Перед публикацией проверяются отмена, версия сборки, поколение проекта,
  состав компонентов, сопоставления и выбранные условия. Обработчики
  нумерации примечаний назначаются только после успешной проверки.
- Уход отменяет загрузку и массовое применение облегчённого режима;
  старое завершение не сбрасывает IsLoading новой сборки. Перед применением
  очередного условия проверяется, что проект не сменился.
- Выгрузка формы 4 во время загрузки или после смены проекта отклоняется.
  Планирование пустой формы при отсутствующей записи формы в каталоге
  сохранено для существующего сценария проекта только с платой.
- Регрессии управляют задержками без sleep: старое семейство/компонент,
  A → B → A, поздний предпросмотр условий, ошибка/восстановление карточки,
  уход/возврат дерева, поздний успех/ошибка формы, смена проекта без
  повторного открытия экрана и запрет выгрузки прежних групп.

Продолжение R1 — split/merge и повторное открытие:

- MultiSplitColumnCommand до изменения коллекции проверяет непустые группы,
  точное покрытие исходных позиций и отсутствие дублей/чужих позиций.
  Распределение копируется при создании команды, чтобы внешние изменения
  списков не меняли поведение redo. Объединение отвергает пересекающиеся позиции.
- При выборе стороны конфликта НТД отсутствующие поля не заполняются
  данными отвергнутой стороны. Для совместимых данных без конфликта
  дополнение недостающих значений сохранено.
- Явный выбор условий столбца отделён от наследования условий компонента.
  SyncColumnsAsync не заменяет такой выбор; null с признаком явного выбора
  означает базовые значения, а не возврат к наследованию.
- .omaps v4 хранит этот выбор и сохраняет явный сброс базы коэффициента.
