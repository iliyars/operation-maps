## Критический пример

У СПНС27-5-05Ч-1 ресурс 180000 хранится как значение семейства; к нему
привязано примечание «Используется в облегченном режиме, при Iвых ≤0,7Iном».
Сейчас снятие флажка удаляет примечание из проекта, но оставляет 180000.
Технически приложение работает согласно текущей модели, однако пользователь
может получить условное значение без обязательного пояснения.
Безусловное значение ресурса в текущей записи не представлено.
Нельзя выдумывать его, брать 0 или считать 180000 безусловным автоматически.

## Целевая модель

1. Основное значение параметра хранится независимо. Может быть неизвестным.
2. Обычное примечание — пояснение к параметру; его выбор не меняет значение.
3. Условие применения — явно классифицированная запись с текстом для Word.
   Оно может менять несколько параметров одного компонента. Одно примечание
   не становится условием автоматически лишь из-за наличия звёздочки.
4. Изменение значения связывает условие, параметр и альтернативное значение.
   Это отсутствующая сейчас связь. Глобальный текст Notes не должен сам
   содержать значения: один текст переиспользуется у разных компонентов.
5. Проект хранит выбранные условия и снимок их значений отдельно от каталога.
   Измеренные значения «в схеме» не меняются от выбора условия.

В интерфейсе обычные примечания и условия доступны рядом с параметрами,
без отдельного редактора режимов. Выбор условия обновляет все связанные
значения. Снятие возвращает основные; если они неизвестны, показывается
«Не задано» и проверка проекта требует уточнения перед экспортом.

Если два выбранных условия задают разные значения одного параметра,
приложение требует разрешить конфликт. Приоритет «последнее выбранное» недопустим.
Несколько поясняющих примечаний без изменения значений могут быть выбраны вместе.
Обязательное условие нельзя просто снять, оставив его значение в документе.

## Импорт Word

Маркер показывает связь текста с ячейкой, но не доказывает наличие
альтернативного режима или безусловного значения. На проверке импорта нужно
явно различать пояснение и условие значения. Для значения только с условием
основное остаётся неизвестным до подтверждения пользователем.

Повторный импорт существующего компонента должен показывать различия:
основные значения, примечания, условия и базовый параметр коэффициента нагрузки.
Обновление должно быть атомарным, сохранять Id компонента и не менять открытые
снимки проектов. Текущая реализация существующие компоненты пропускает.

## Порядок перехода

1. Добавить явную связь условия с альтернативными значениями и проверки
   конфликтов; не удалять таблицы прежних режимов до проверки старых проектов.
2. Реализовать проверку классификации при импорте и обновление существующих
   компонентов с просмотром различий. Не переклассифицировать старые Notes
   автоматически по словам «режим» или по тексту.
3. Перенести выбор условий к параметрам, связать его с расчётами и Word.
4. Сохранять снимок выбора в новой версии .omaps. Старые файлы должны открываться
   без потери текста; неоднозначные условные значения требуют проверки.
5. После резервного копирования разобрать текущие четыре связи с примечаниями.
   Объединение дублей текста не должно удалять связи или угадывать семантику.
6. Проверить исходный Word для базовых параметров коэффициентов нагрузки.

## Критерии готовности

- Поясняющее примечание можно выбрать и снять без изменения значения.
- Условие изменяет все связанные параметры и формирует обязательный текст Word.
- При снятии условия возвращается основное значение; неизвестное не подменяется.
- Противоречащие условия не применяются молча.
- Выбор, пустой выбор и неизвестные основные значения переживают сохранение,
  открытие проекта и разделение столбцов.
- Повторный импорт обновляет запись по подтверждённым различиям, без дублей.
- Пройден реальный путь Word → каталог → XML → проект → Word.
