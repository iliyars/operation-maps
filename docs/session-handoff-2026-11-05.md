## Следующие шаги

После сохранения итогового Word программа предлагает открыть его.
`IDocumentLauncher` использует ассоциацию DOCX в Windows; в тестах заменён
заглушкой, редактор реально не запускается. Проверены Да/Нет/Отмена,
ошибка открытия с сохранением DOCX и отсутствие предложения при занятом
файле (`ReportOpeningTests`, 5 passed).

`IDialogService` теперь показывает `MessageDialog` в теме приложения:
русские Да/Нет/Отмена/ОК, прокрутка сообщений и отдельный итоговый вопрос.
Вызовы «О программе», предупреждение о восстановлении и проверка БД тоже
переведены на сервис. Два нативных диалога в App оставлены как аварийный
резерв при ошибке запуска/необработанном исключении. Проверен рендер обеих
тем, кнопки по умолчанию и ограничение высоты на длинном сообщении.

Закрыта геометрия карт из R4: `WordTemplateValidator` проверяет физические
ячейки и коллизии до заполнения Word. Используется также при проверке
экспорта и в обзоре проекта; проверки DOCX в UI выполняются в фоне.
Все 14 комплектов прошли. Семантическое соответствие сидеру/ГОСТ и
пагинация в Word остаются отдельными открытыми задачами.

Закрыта привязка примечаний Word из R3: неизвестные/неоднозначные маркеры
сохраняются в значении. `WordImportedComponent.ImportErrors` объединяется
для повторных слотов, показывается в UI и проверяется перед записью.
Проблемный компонент нельзя выбрать для импорта; исправление источника
и повторное чтение снимают блокировку. Не создаются даже пустые типы.
Разные собственные формы одного компонента тоже диагностируются.
Числа в скобках (диапазоны, допуски, база Кн) остаются данными.
Подробности — `docs/word-import-notes.md`.

Обязательное требование Ильи: несколько значений одного параметра по режимам
сохраняются раздельно. При наличии облегчённого значения без нормального
компонент требует редактирования независимо от IsRequired/NeedsAdminReview.
`NormalRegimeDataCheck` используется сопоставлением, справочником, проверкой
экспорта и подтверждением записи. Пометка перечисляет параметры, не пропадает
при выборе облегчённого режима и пересчитывается после исправления.
Проверены раздельное хранение/переключение, неизвестные значения, собственная
форма, запрет подтверждения, исправление через редактор и обе темы.

Завершён цикл добавления/проверки из R3: мастер проекта позволяет выбрать
существующий тип для пустого или неизвестного XML-типа. Имя сохраняется,
запись требует проверки. Сквозные тесты проходят от мастера/Word-импорта
через SQLite до очереди справочника и подтверждения администратором.
Добавления из администраторского справочника сразу проверены.

Сопоставление из R3 проверено: точное имя приоритетно, нормализованный
кандидат используется только при однозначности. Для нескольких семейств
теперь выводится явное предупреждение с вариантами без присвоения семейства
или его форм. Проверки охватывают оба порядка семейств, различия номиналов,
допусков, единиц и ОС/ОСМ; исходные обозначения не переписываются.

Закрыта запись Word из R4: все экспорты и JSON-проекты используют
`AtomicFileWriter`. Сначала полностью записывается отдельный временный файл
в той же папке, затем выполняется замена. Старый файл не удаляется заранее;
ошибка/отмена до замены его сохраняет. Проверены занятые документы,
повторная попытка и конкурирующие записи (`AtomicFileWriterTests`).

XML-импорт больше не отбрасывает компоненты с неизвестным типом, читает
кодировку из XML/BOM и показывает предупреждения по записям. Неверная
структура не заменяет текущий проект пустым. Проверены восемь реальных
перечней и сквозной путь неизвестного компонента в несопоставленные.
Подробности — `docs/xml-import.md`.

через push. Инструкция по локальным базам — `docs/reset-local-database.md`.
