# Общий справочник в сетевой папке

Пока нет сервера базы данных, справочник (`catalog.db`) лежит в общей
папке, и все копии программы работают с одним файлом.

## Ограничение

SQLite в сетевой папке выдерживает много одновременных читателей, но
одновременная **запись** с нескольких компьютеров может повредить файл.
Поэтому:

- структуру базы обновляет и формы досеивает **только копия
  администратора** (`UpdateSchemaOnStartup: true`);
- остальные копии базу не создают и не обновляют, а при несовпадении
  версий показывают понятное сообщение;
- раз в день (при первом запуске любой копии) и перед каждым обновлением
  структуры делается резервная копия в папку `backups` рядом с базой;
  копии старше `BackupRetentionDays` дней удаляются.

Это временное решение для небольшой команды. Для одновременной работы
многих людей нужен сервер базы данных (SQL Server Express — бесплатный).

## Настройка (`appsettings.json` рядом с `OperationMaps.Wpf.exe`)

Копия администратора:

```json
{
  "ConnectionStrings": { "Catalog": "Data Source=\\\\server\\share\\OperationMaps\\catalog.db" },
  "Catalog": { "UpdateSchemaOnStartup": true, "BackupRetentionDays": 14 }
}
```

Копии пользователей — то же самое, но `"UpdateSchemaOnStartup": false`.

- Путь можно указать сетевой (`\\server\share\...`, в JSON обратные слэши
  удваиваются), локальный (`D:\\Shared\\catalog.db`) или относительный
  (`catalog.db` — рядом с программой). Переменные окружения раскрываются
  (`%USERPROFILE%\\...`).
- У пользователей нужны права на **чтение и запись** файла и папки: SQLite
  создаёт рядом служебный файл на время записи, а резервные копии пишутся
  в `backups`.

## Порядок обновления программы

1. Администратор запускает **новую** версию первым — она делает резервную
   копию и обновляет структуру базы.
2. Остальным раздаётся та же версия. Пока у пользователя старая версия, а
   база уже новая, программа попросит обновиться и не запустится — это
   защищает базу от записи несовместимой версией.

## Если база повредилась

Закрыть программу у всех, заменить `catalog.db` последней копией из
`backups` (переименовав её в `catalog.db`).
